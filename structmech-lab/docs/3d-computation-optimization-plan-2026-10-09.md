## 1. 建议与范围

建议按“建立验证基线 → 修正计算与结果解释 → 复用计算 → 优化三维显示 → 扩展分析能力”的顺序推进。当前最有价值的改进，是让每一次计算结果可信、可追溯，并避免同一结构被重复装配和求解。

本计划把“三维计算”理解为完整工作链：空间模型、荷载、单元与约束、线性方程求解、多工况组合、结果恢复、三维展示和报告。第一轮以浏览器中的空间杆系线弹性静力分析为主；目标用户和规模暂按教学及中小型空间框架分析设定。实际规模通过基准测试确认，不能先承诺支持多少万节点。

第一轮不同时引入板壳、实体、动力、材料非线性和规范设计验算。它们分别需要新的单元理论、数据、求解流程和验证体系，适合作为后续独立项目。P-Δ、Timoshenko 梁、刚性楼板也先保留明确的扩展路径。

研究阶段只新增本计划文档。随后依据“开始写”实施了首批计算正确性修改；详见 [首批实施与验证记录](./3d-computation-first-batch-2026-10-09.md)。尚未提交、推送或部署。

### 2.3 已查阅的资料如何影响决策

以下为本次查阅的官方文档、项目原始文档，共 16 项；完整链接与用途见第 10 节。资料提供方法依据，项目瓶颈仍须通过本地测量确认。

## 4. 目标架构与关键决策

### 4.1 保留界面模型，建立可复用的数值上下文

推荐将状态拆成四类：

1. **结构状态**：坐标、连接、单元类型、材料截面、roll、约束、弹簧和释放；决定刚度。
2. **荷载状态**：工况荷载、自重和组合系数；通常只改变右端与结果恢复所需荷载项。
3. **分析配置**：后端、容差、预条件器、结果精度；决定求解或结果缓存。
4. **显示状态**：相机、选中对象、图层、放大倍数；不得触发结构求解。

为结构和荷载引入版本号与可验证指纹。版本号用于交互效率，指纹用于跨文件/缓存一致性；不能只比较对象引用。材料、截面、roll、弹簧与释放均必须进入刚度失效规则。

Worker 持有 `PreparedAnalysis`：DOF 映射、单元局部轴/刚度/释放映射、CSR、矩阵诊断，以及可复用的分解或预条件器。协议分为准备结构、求解工况集合、取消请求、释放缓存；各请求带模型版本和请求编号。

### 4.2 缓存必须按依赖失效

| 改动 | 重装配刚度 | 重建分解/预条件器 | 重算工况 | 重建基础三维几何 |
|---|---|---|---|---|
| 相机/选择/图层/变形倍率 | 否 | 否 | 否 | 否；只更新对应显示数据 |
| 只改某工况荷载 | 否 | 否 | 受影响工况；更新相关组合 | 否；更新荷载/结果图层 |
| 只改组合系数 | 否 | 否 | 线性模式可由基础结果重建组合 | 否 |
| 材料/截面数值/roll/弹簧/释放 | 是 | 是 | 全部相关工况 | 杆中心线通常不变；截面/局部轴图层按需更新 |
| 坐标/连接/节点增删/约束 | 是 | 是 | 全部相关工况 | 是；可进一步局部更新 |

符号分析只在确认稀疏模式相同后复用。当前装配会舍弃零项，坐标角度、释放或数值改变可能改变实际模式；可使用按拓扑预分配的稳定模式，或重新验证模式指纹。

### 4.3 求解器采取渐进路线

| 路线 | 建议 | 采用条件 |
|---|---|---|
| 现有 JS CSR + PCG | 第一轮主线 | 稳定线弹性模型、统一真实残差验证；先复用和降低分配开销 |
| 小模型 dense | 保留回归参照 | 设自由 DOF 与内存上限，显式分解失败；它与稀疏法共享单元公式，不能替代独立验证 |
| 块 Jacobi / 不完全 Cholesky | 分别做受控比较 | 需保持 SPD，释放后小块可能奇异；预条件器构建时间和内存计入总耗时 |
| WASM 稀疏直接法 | 在基准完成后做验证原型 | JS 确有瓶颈，或多右端复用收益明显；精度、资源与发布兼容性同时达标 |
| 非正定系统的通用求解器 | 后续按模型需求引入 | 先判断是建模机构还是合法不定方程；不能用更通用算法掩盖不稳定模型 |
| 多线程 / GPU | 后置研究 | 数据规模、任务分解、传输与部署条件证明有收益后再投入 |

现有 `wasm-sparse` 是不可用适配器加 JS 回退，不能将其描述成已有 WASM 加速。若做原型，先评估 Eigen 的 SPD 稀疏 Cholesky/LDLT 接口；若研究 SuiteSparse，需核对选定版本、具体子模块、依赖和许可证。Eigen 的 `SimplicialLDLT` 文档列为 SPD 求解器，不能当作任意对称不定系统的带主元 LDLT。[Eigen](https://eigen.tuxfamily.org/dox/group__TopicSparseSystems.html)、[SuiteSparse](https://github.com/DrTimothyAldenDavis/SuiteSparse/blob/dev/README.md)

当前静态部署的响应头能力尚未核验；因此先支持普通 Worker 和单线程 WASM，跨源隔离成立后再考虑 pthreads。[Emscripten 条件](https://emscripten.org/docs/porting/pthreads.html)

## 5. 正确性与性能基准设计

### 5.1 三层交叉验证

**第一层：解析题。** 覆盖轴向伸长 PL/EA、纯扭转 TL/GJ、悬臂端荷载 PL³/3EI、悬臂均布 qL⁴/8EI、简支均布 5qL⁴/384EI、梯形荷载、端部释放、弹簧支座。简支梁算例还必须检查跨中最大挠度，不能仅对比端点。

**第二层：不变量与错误模型。** 整体旋转后的物理结果转换一致；节点/杆件顺序不改变全局结果；反转杆件端点后按明确符号映射比较；细分杆件不改变相同物理模型的线性结果；无荷载给零响应但不掩盖机构；对称性、能量及力/矩平衡成立。近竖杆跨越局部轴参考切换阈值时，需显式保持相同截面朝向，不能把默认朝向变化误当成数值不连续。

**第三层：独立实现。** 主对照使用 OpenSees 的相同线弹性梁柱模型；用 Pynite 补充易复算的空间框架与荷载算例。导出坐标、约束、单位、局部轴、荷载方向、roll、释放和采样位置；固定软件版本与脚本。先统一约定再对照数值，不能直接比较各软件默认局部 My/Mz。[OpenSees](https://opensees.github.io/OpenSeesDocumentation/user/manual/model/elements/elasticBeamColumn.html)、[Pynite](https://pynite.readthedocs.io/en/latest/member.html)

首批至少包含：双向弯曲且 Iy≠Iz 的悬臂、roll=0/30/90°、竖杆/斜杆、3D 门架、带支撑两层框架、节点弹簧、一个含非零行线性相关的机构、一个无荷释放转角的合法模型，以及不同轴向/弯曲刚度量级模型。

### 5.2 数值验收规则

以下是拟定门槛，不是当前测量成绩；基线阶段确认尺度与适用条件。

- 内部全程保留 Float64 原始数值，格式化在显示/报告边界进行；组合、包络、平衡检查不得使用已舍入值。
- 每次最终求解重新计算原系统 `r = f - Ku`。同时报告真实相对残差和后向误差；零荷载/极小荷载使用绝对容差，避免除零或无限放大小量。
- 后向误差可采用 `||r|| / (||K||·||u|| + ||f||)`；范数保持一致。对于平移/转角混合 DOF，记录采用的无量纲缩放，使误差比较有定义。
- 拟定良态解析算例位移/反力/内力相对误差不超过 `1e-6`；接近零的结果使用按单位定义的绝对误差。外部比较先以 `1e-5` 为调查门槛；误差来源不明时不得通过放宽阈值结案。
- PCG 默认真实相对残差目标 `1e-8`；达不到时按结构化原因标记未收敛。小残差不能保证病态模型的位移误差小，需结合条件/稳定性诊断。
- 力平衡按 kN、矩平衡按 kN·m 分别评价。尺度来自荷载分量绝对值之和及特征长度，不能使用可能抵消为零的净荷载作为唯一尺度。
- 局部释放恢复检查释放端内力、单元平衡与全局平衡；失败结果退出包络与通过性检查。警告结果可以按明确规则参与，但必须显示警告来源。
- 能量检查用于无弹簧/含弹簧、无释放/含释放的相应完整系统；它只是补充，不能替代独立算例。

### 5.3 性能基准矩阵

建立固定、可导入的模型集，记录实际节点、杆件、总 DOF、自由 DOF、nnz 和约束率。

| 模型族 | 规模档位（拟定） | 用途 |
|---|---|---|
| 单梁与小框架 | 10～100 节点 | 核实 Worker 冷启动、单次小模型与端到端延迟 |
| 规则空间框架 | 约 500、1000、2000 节点 | 单工况与 5/20/50 工况；冷启动和缓存命中分开测 |
| 带斜撑/释放/不同截面的空间杆系 | 与规则框架相近的 DOF | 测收敛、稀疏模式和三维拾取，避免只优化规则网格 |
| 大规模压力测试 | 约 5000 节点起，逐档增加 | 找资源边界；不作为预先承诺的交付规模 |
| 病态和机构 | 规模小、参数受控 | 看失败诊断是否可靠，避免将快速错误结果计入成绩 |

超过现有参数生成器上限的模型使用独立基准夹具，不先扩大用户输入上限。

记录完整链条：准备模型、装配、矩阵诊断、分解/预条件器、每工况求解、后处理、Worker 编码与传输、结果到达、首帧显示；同时记录取消响应、长任务、FPS/frame time、draw calls、CPU/GPU 内存可用指标。浏览器不提供精确内存时明确标注估算方法。

同设备、同浏览器版本、同模型和生产构建进行重复测试：预热 3 次，常规场景采集不少于 20 次，输出中位数与 P95；重型场景可减少次数但必须披露。Worker 冷启动单独计数，不混入热缓存结果。计时应只累计本次实际工作，不能把第一次刚度装配时间重复算入每个工况。

阶段目标：只改荷载时刚度装配计数为 0；同结构批量工况最多装配一次；缓存成立时分解/预条件器最多构建一次；选择和切换内力分量时求解计数为 0。性能提速倍数在有基线后再设定，不提前承诺“快 10 倍”。交互目标暂定常用中型模型 frame time 中位数≤16.7 ms、P95≤33.3 ms，取消反馈≤200 ms；设备与模型条件必须随结果公开。

### 阶段 B：让同一个结构只准备一次

| 任务 | 内容、验收与验证 | 依赖 | 主要落点 / 范围 |
|---|---|---|---|
| B1 计算上下文缓存 | 增加结构/荷载/配置版本；缓存矩阵诊断、分解或缩放预条件器。验收：只改荷载不重装配，改截面/roll/弹簧/释放必失效；用计数器验证。 | 检查点 A | `spaceSolver.ts`、新增上下文模块、相关测试；M |
| B2 Worker 批量与取消 | 新增 prepare/solveMany/cancel/dispose；结构缓冲区和结果按规模打包。验收：旧版本结果不能覆盖新版本；取消及时；重复计算不过度创建 Worker。 | B1 | Worker、hook、协议文件与测试；M |
| B3 组合和包络闭环 | 界面接入多目标求解、结果缓存及真正包络；失败目标单列，来源可点击。线性模式允许叠加基础工况原始响应。验收：组合与直接组合荷载复算一致。 | B1、B2、A5 | `spaceModel.ts`、工作区、新增工况结果管理模块与测试；M |
| B4 调度与降级体验 | 计算进度按实际准备/求解/后处理阶段呈现；大模型 Worker 故障不能直接把重计算搬回主线程。验收：错误有恢复动作，小模型允许受控同步回退，模型过期和失败状态清楚。 | B2、B3 | hook、工作区、诊断面板与测试；M |

组合优化只能叠加带符号的位移、单元端力、荷载/分段响应系数，再重算合量和极值。不能叠加 `maxDisplacement`、绝对最大弯矩或各工况最大值；不同工况的控制位置可能不同。P-Δ、单向受力杆、接触或任何改变刚度的分析不适用这一线性缓存规则。

取消有两种层次：批量工况间可通过分段异步调度处理消息；一个长时间同步求解无法仅靠普通 cancel 消息立即停止。第一轮保留 terminate 的硬取消能力并明确缓存会丢失；若改成可让出的迭代循环，再验证缓存保持和响应延迟。不能用“忽略旧结果”代替停止后台计算。

**检查点 B：** 同模型 20 工况的装配/分解次数符合设计；只改荷载有明确缓存命中；批量包络完整；取消和失败不冻结界面；将冷启动与热缓存性能分开公布。

## 8. 主要风险及控制方式

| 风险 | 控制方式 |
|---|---|
| 同源 dense/PCG 对照掩盖共同公式错误 | 解析题与独立 OpenSees/Pynite 三层验证；局部轴和单位映射记录到夹具 |
| 缓存失效遗漏，旧结果看似正确 | 结构/荷载/配置版本分离；参数变更矩阵测试；结果带模型指纹 |
| 成功回退仍沿用失败提示或错误后端 | 保存求解尝试历史和最终状态；最终后端/最终残差单列 |
| 转移 ArrayBuffer 后主线程数据被 detach | 转移专属数值副本，界面数据保留；或一次上传后 Worker 持有；不转移仍在使用的状态数组 |
| 组合叠加绝对值与最大值导致错误 | 只叠加原始带符号响应，组合后重算极值；状态和线性适用性显式检查 |
| 简单 CG 停滞规则导致良态模型误退出 | 不要求残差逐步单调；周期复算真实残差；停滞窗与退出条件由算例验证 |
| 图形合批破坏拾取、显示朝向或资源管理 | 稳定对象 ID、局部轴共享、资源所有权、浏览器回归与内存观察 |
| 增加 WASM 只改善核心耗时，端到端更慢 | 将加载、转换、初始化、内存和包体积计入比较；按收益决定是否启用 |
| 三维组件/求解器过大导致同步重构风险 | 先定义类型与验证夹具，再按任务提取小模块；每个提交保留可用路径 |
